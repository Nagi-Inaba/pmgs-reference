# ADR 0002：監査用レコードと意味レコードを分離する

- 状態：採用
- 日付：2026-08-08

## 判断

SQLiteは、CSV全行、XMLの対象要素、HTMLの表行を`source_record`へJSONとして保持する。

同時に、照会に必要な分類、公式本文、関係、文書、ページ本文を型付きテーブルへ格納する。

## 理由

PMGSにはCSVだけで4,289,667行があり、入力形式ごとに列と意味が異なる。

型付きテーブルだけでは、未知列、継続行、引用符不足を後から再検証しにくい。
一方、原行JSONだけでは正確な分類照会、階層、関係、FTSを安定した契約で提供できない。

両者をlineageで接続することで、元行の監査可能性と利用面の単純さを両立する。

## 帰結

- 正本DBは元CSVより大きくなるため、実データbuild前に空き容量を測る。
- 同じ公式本文を不必要に複製せず、長文資料は`document_text`へ置く。
- 公開exportへ`source_record`や正本DBをそのまま出さない。
- 型付き変換に失敗しても原行を黙って捨てず、`build_issue`へ記録する。
